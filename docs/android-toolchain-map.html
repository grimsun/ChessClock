Android Toolchain Map

Building one small Kotlin app touches about a dozen tools, each with its own version number. This page explains what each one does, where its version is set, and which ones force upgrades on the others. Every example comes from your own ChessClock setup.

What forces what

Why one upgrade drags others along

These tools don't upgrade independently. Each rule below sets a minimum or maximum on another tool. Moving ChessClock from 2022 to now ran into almost all of them.

AGP 9.4.1needs at leastGradle 9.x

Every AGP release states a minimum Gradle version. AGP 9 doesn't load on Gradle 7.3.3, so the two always move together.

AGP 9needs at leastJDK 17

Your Mac had no system Java at all (java -version fails), so the build uses the JDK 25 that ships inside Android Studio.

Gradle 7.3.3can't run onJDK 21

Old Gradle doesn't run on newer Java. That's why I edited the wrapper's version by hand instead of asking the old Gradle to upgrade itself.

Studio 2024.2can't openAGP 9.4.1

Studio only syncs AGP versions it was released alongside or after. The terminal build worked, but Studio refused the project until it was updated to 2026.2.

AndroidX librariesneed at leastcompileSdk N

Each library includes metadata listing the compileSdk and AGP it requires, and the build fails if yours is lower. Bumping libraries often forces a compileSdk bump.

compileSdk 37needs a recentAGP

Each AGP release is tested up to a certain API level. A brand-new API level usually needs a fairly new AGP.

targetSdk ≥ 35changesruntime behavior

When targetSdk is 35 or higher, Android draws the app edge to edge, behind the status bar. In ChessClock this hid the top of the Settings list under the app bar until both screens were changed to pad for the system bars.

System image APImust be ≥minSdk 28

The app installs on any emulator or phone at API 28 or above, so your API 33 and 35 virtual devices can run it too.

minSdk 28

Who can install it?

Phones older than this can't install the app. It also limits which APIs you can call without a version check.

compileSdk 37

Which APIs can the code see?

This only affects compiling. It decides which android.jar is used, so newer APIs become visible to your code. It doesn't change how the app behaves.

targetSdk 37

Which behavior rules apply?

Android keeps old behavior for apps with an older target. Raising it opts into new rules such as edge-to-edge drawing. Google Play requires a recent target for new uploads.

Three Javas

Java shows up three times, at three different versions

25

The JDK that runs Gradle

A program on your Mac, found through JAVA_HOME. Yours is Android Studio's bundled JBR. It only has to be new enough for AGP and not too new for Gradle.

17

The target for your code

compileOptions sets which Java language features and bytecode level your compiled code uses. AGP keeps Kotlin's jvmTarget matched to it.

ART

What the phone actually runs

Android doesn't run Java bytecode. D8 converts it to DEX for the Android Runtime (ART), and rewrites newer Java features so older phones can run them. That's why a Java 17 target still works on API 28.

One build, step by step

What ./gradlew installDebug actually does

  1. The wrapper picks Gradle. gradlew reads gradle-wrapper.properties, downloads Gradle 9.8.2 into ~/.gradle/wrapper/dists if it's missing, and starts a Gradle background process on your JDK. This is why you never install Gradle globally.

    Gradle

  2. Settings load. settings.gradle lists where plugins and libraries come from (Google's Maven repository and Maven Central) and which modules exist (:app).

    Gradle

  3. AGP loads and finds the SDK. AGP is downloaded from Google's Maven repository like any library, then finds the SDK through local.properties.

    AGP

  4. Dependencies resolve. AndroidX and Material are downloaded once into ~/.gradle/caches, and AGP checks each one's compileSdk requirement.

    Gradle

  5. Manifests merge. Your AndroidManifest.xml is combined with every library's manifest. The namespace setting decides the package name of the generated R class.

    AGP

  6. Resources compile. aapt2 compiles layouts, strings and icons and generates R.layout.activity_main and friends.

    aapt2

  7. Kotlin compiles. Your .kt files compile against platforms/android-37.0/android.jar into .class files.

    kotlinc

  8. Code is converted to DEX. D8 converts your classes and every library's classes into classes.dex.

    D8

  9. The APK is packaged and signed. Everything is zipped into app-debug.apk and signed with the auto-generated ~/.android/debug.keystore.

    build-tools

  10. The APK installs. adb pushes the APK to every connected device or running emulator.

    adb
The emulator

Emulator, system image and AVD are three separate things

Emulator 37.2.12

The program, a heavily modified QEMU. It updates on its own schedule and can boot any system image.

System image API 37.0

An Android OS build. google_apis_playstore includes the Play Store, while google_apis doesn't but allows root access. Choose arm64-v8a on Apple Silicon.

AVD Pixel_9_API_37

One virtual phone: a hardware profile (screen, RAM), a system image and its own disk with installed apps. You can have many AVDs; you now have three.

Upgrade order

How to revive an old project next time

This is the order used for ChessClock. Each step makes the next one possible.

  1. Update the SDK tools. Get cmdline-tools first, then run sdkmanager --update and install the newest platform, build-tools and system image.
  2. Point at a modern JDK. export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home", which your ~/.zshrc now sets along with ANDROID_HOME and PATH.
  3. Bump Gradle by hand in gradle-wrapper.properties, then run ./gradlew wrapper --gradle-version X to regenerate the wrapper scripts.
  4. Bump AGP and read its release notes for breaking changes. For AGP 9 those were: package moves to namespace, Kotlin is built in, and kotlinOptions is removed.
  5. Raise compileSdk and targetSdk, then libraries. Look up current versions on Google's Maven repository.
  6. Build with --warning-mode=all and fix warnings coming from your own code. Warnings coming from inside AGP aren't yours to fix.
  7. Run it on an emulator and check the screens that targetSdk changes, such as edge-to-edge drawing and permissions.
  8. Update Android Studio so it can sync the new AGP.
# the everyday loop (JAVA_HOME and PATH come from ~/.zshrc)
cd ~/Dev/ChessClock
./gradlew assembleDebug           # build the APK
./gradlew testDebugUnitTest       # JVM unit tests
./gradlew installDebug            # build + adb install
adb shell am start -n com.lab.chessclock/.MainActivity
